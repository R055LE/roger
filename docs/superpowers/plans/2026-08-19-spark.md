# Spark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Roger a daily, grounded, unprompted public post — one real feed item spotlighted
with a discussion question — distinct from the digest's everything-roundup.

**Architecture:** New `roger/brains/spark.py`, reusing `roger/brains/digest.py`'s `_collect_new`
against the same `feeds` table. A new `"spark"` brain identity (own model chain/budget) picks one
item and writes a blurb + question via a small hand-rolled response parser (no JSON mode
available in the LLM wrapper). Scheduled via the same `tasks.loop` shape as Digest, gated the same
way (loop only starts once a channel is configured — no DM fallback). Also triggerable via a new
`run_spark` admin tool, mirroring `run_digest`.

**Tech Stack:** Python 3.12, discord.py `tasks.loop`, the existing `LLM`/`Store` wrappers,
`aiosqlite` (no schema change), pytest.

## Global Constraints

- Ruff line-length is 100 chars (`pyproject.toml`). Keep every line, including in f-strings and
  log calls, under that.
- No new SQLite table and no migration. Spark reads `feeds` via `store.list_feeds()` (existing)
  and writes only via `store.mark_seen(pairs)` (existing) — it never adds a store method.
- `spark_channel_id` is required, no DM fallback. Unset means the feature is off: the scheduled
  loop simply never starts (same pattern as the **public** digest's `digest_channel_id`, not the
  personal digest's unconditional-start-and-self-gate pattern).
- `"spark"` is a new brain identity. It needs an entry in **every** per-brain dict in
  `roger/llm.py`: `_TEMPERATURE`, `_MAX_TOKENS`, `self._chains`, `self._caps`, `self._usd_caps`.
  Missing any one of these raises `KeyError` the first time `llm.complete("spark", ...)` runs.
- `_SPARK_OK_PREFIXES = ("posted", "no new items")` — exactly `_DIGEST_OK_PREFIXES`'s shape, not
  `_PERSONAL_DIGEST_OK_PREFIXES`'s (which additionally OKs "not configured" because that loop
  starts unconditionally; Spark's doesn't).
- Default `SPARK_HOUR = 7`, existing `DIGEST_HOUR = 8`. Spark must run before Digest so that an
  item Spark marks seen doesn't get redundantly summarized by the roundup later the same day.
- Tests use a real `Store` plus hand-written fakes (`FakeClient`, `FakeChannel`, `FakeLLM`), never
  `unittest.mock` — matches `tests/test_digest.py`'s existing style throughout this codebase.
- ADR number is `0011` (latest existing is `0010`).

```python
"""Spark brain: one grounded item + a discussion question, posted to a public channel (roadmap
item 2 -- see docs/superpowers/specs/2026-08-19-spark-design.md).

No user input anywhere in this path. Runs on a daily ``discord.ext.tasks`` loop and is also
triggerable via the ``run_spark`` tool. Reuses the same feed list and collection logic as the
digest; the only new step is asking the model to *choose* one item and write a question about it,
instead of summarizing everything.
"""

from __future__ import annotations

import datetime
import logging
from typing import Any
from zoneinfo import ZoneInfo

import discord

from roger.brains.digest import _collect_new
from roger.llm import LLM, BudgetExceeded, LLMConfigError
from roger.store import Store

log = logging.getLogger("roger.spark")

SPARK_SYSTEM = (
    "You are Roger. Below is a numbered list of RSS/Atom items. Pick the ONE most interesting "
    "or discussable item -- favor items that raise a real question or invite an opinion over "
    "routine announcements. Respond in EXACTLY this format, nothing before or after it:\n\n"
    "ITEM: <number>\n"
    "BLURB: <2-3 short, deadpan sentences about the item, grounded only in its title and "
    "summary below -- never state anything about it that isn't in the text you were given>\n"
    "QUESTION: <one open-ended question inviting replies>"
)


class SparkParseError(ValueError):
    """The model's response didn't match the required ITEM/BLURB/QUESTION format."""


def _format_candidates(entries: list[dict[str, Any]]) -> str:
    lines = []
    for i, e in enumerate(entries, start=1):
        lines.append(f"{i}. {e['title']}\n   {e['summary']}")
    return "\n".join(lines)


def _parse_choice(text: str, n: int) -> tuple[int, str, str]:
    """Parse the model's ITEM/BLURB/QUESTION response. Raises SparkParseError on any mismatch."""
    fields: dict[str, str] = {}
    key: str | None = None
    for line in text.strip().splitlines():
        for prefix in ("ITEM:", "BLURB:", "QUESTION:"):
            if line.startswith(prefix):
                key = prefix[:-1]
                fields[key] = line[len(prefix) :].strip()
                break
        else:
            if key is not None:
                fields[key] += " " + line.strip()

    if not all(k in fields for k in ("ITEM", "BLURB", "QUESTION")):
        raise SparkParseError(f"missing field(s) in response: {text!r}")

    try:
        index = int(fields["ITEM"])
    except ValueError as exc:
        raise SparkParseError(f"ITEM was not an integer: {fields['ITEM']!r}") from exc
    if not (1 <= index <= n):
        raise SparkParseError(f"ITEM {index} out of range 1..{n}")

    blurb, question = fields["BLURB"].strip(), fields["QUESTION"].strip()
    if not blurb or not question:
        raise SparkParseError("BLURB or QUESTION was empty")

    return index - 1, blurb, question


async def _choose(entries: list[dict[str, Any]], llm: LLM) -> tuple[dict[str, Any], str, str]:
    """Ask the model to pick one entry and write a blurb+question. Raises SparkParseError."""
    body = _format_candidates(entries)
    messages = [
        {"role": "system", "content": SPARK_SYSTEM},
        {"role": "user", "content": body},
    ]
    response = await llm.complete("spark", messages)
    text = response.choices[0].message.content or ""
    index, blurb, question = _parse_choice(text, len(entries))
    return entries[index], blurb, question


async def run_spark_job(*, client: Any, settings: Any, llm: LLM, store: Store) -> dict[str, Any]:
    channel_id = settings.spark_channel_id
    if channel_id is None:
        return {"status": "spark not configured (SPARK_CHANNEL_ID unset)"}

    feeds = [row["url"] for row in await store.list_feeds()]
    entries = await _collect_new(feeds, store)
    if not entries:
        return {"status": "no new items"}

    try:
        chosen, blurb, question = await _choose(entries, llm)
    except BudgetExceeded:
        log.warning("spark skipped: daily token budget hit")
        return {"status": "budget exceeded; skipped"}
    except LLMConfigError as exc:
        return {"status": f"spark brain not configured ({exc})"}
    except SparkParseError as exc:
        log.warning("spark skipped: unparseable model response (%s)", exc)
        return {"status": "unparseable response; skipped"}

    channel = client.get_channel(channel_id)
    if channel is None:
        return {"status": f"spark channel {channel_id} not found"}

    today = datetime.datetime.now(ZoneInfo(settings.tz)).strftime("%Y-%m-%d")
    embed = discord.Embed(
        title=chosen["title"], url=chosen["link"] or None, description=blurb[:4096]
    )
    embed.add_field(name="Discuss", value=question[:1024], inline=False)
    embed.set_footer(text=f"Spark -- {today}")
    try:
        await channel.send(embed=embed)
    except discord.DiscordException:
        log.exception("failed to deliver the spark post")
        return {"status": "delivery failed; not posted"}

    # Mark only the chosen item seen -- passed-over items stay eligible for the digest roundup.
    await store.mark_seen([(chosen["feed_url"], chosen["id"])])
    return {"status": "posted", "title": chosen["title"]}
```

- [ ] **Step 7: Write ADR-0011**

Create `docs/decisions/0011-spark-grounded-discussion-prompts.md`:

```markdown
# ADR-0011: Spark stays grounded, marks its pick seen, and gets its own budget

- **Status:** Accepted
- **Date:** 2026-08-19

## Context

Roadmap item 2 ("Spark") asked for a new scheduled capability that posts unprompted to a public
channel to spark discussion. That's a new class of unprompted public output — Digest summarizes
neutrally and Giga Brain's periodic check-in is DM-only/owner-facing; Spark is the first thing
that writes something opinionated-adjacent (a discussion question) to a channel other members
read, with no human reviewing it first.

Three choices needed deliberate tradeoffs, not just "do what Digest does":

1. Where does Spark's content come from, and how far can the model range from it?
2. Digest and Spark would both read the same `feeds` list and the same `seen` dedupe table. Does
   Spark's pick count as "covered" for Digest's roundup, or not?
3. Does Spark share Digest's model/budget, or get its own?

## Decision

**Grounded-only, never free-generated.** Spark's prompt hands the model a numbered list of
already-fetched feed items and asks it to pick one and write about it — the model never invents a
topic from nothing. The system prompt explicitly instructs the blurb to state only what's in the
item's own title/summary. This is the same "the tool grounds it in reality" shape §9 already uses
for feed curation (`suggest_feeds` validates against the live web before the model can recommend
a feed), applied to content generation instead of feed validation.

The model's response is parsed with a small fixed-format parser (`ITEM:`/`BLURB:`/`QUESTION:`),
not JSON mode — the LLM wrapper has no structured-output support today, and a malformed or
out-of-range response is treated as a clean skip (nothing posted, nothing marked seen, retried
next tick) rather than a best-effort guess at which item a question is "about."

**Spark marks its chosen item seen; nothing else changes about dedup.** Spotlighting an item
counts as "covered" the same day — the digest roundup that runs afterward (`SPARK_HOUR=7` before
`DIGEST_HOUR=8`) won't redundantly re-summarize it. Items Spark saw but didn't pick are left
untouched and remain eligible for the roundup. This relies on the `seen` table's existing global
`(feed_url, entry_id)` keying (documented as a caveat in §9 already, from the personal digest) —
Spark doesn't change that shape, it just becomes a second writer into it, ordered deliberately by
the hour default rather than left to chance.

**Spark gets its own model chain and budget** (`MODEL_SPARK`, `DAILY_TOKENS_SPARK`,
`DAILY_USD_SPARK`), not `MODEL_DIGEST`. `ROADMAP.md` item 3 ("model allocation pass") had
explicitly deferred this for the personal digest, on the grounds that there was no real
editorial-generation output yet to tune a model choice against. Spark is that output: picking the
most discussable item and writing a question that actually invites a reply is a different task
from digest's neutral, exhaustive summarization, and benefits from a different temperature (0.6
vs digest's 0.3) and plausibly a different model entirely.

## Consequences

- One more brain identity to keep in sync across `roger/config.py` and every per-brain dict in
  `roger/llm.py` — a maintenance cost the codebase already pays three times over (admin, ambient,
  digest, gigabrain) and now pays a fifth time.
- The `seen` table's shared-keying caveat (§9) now has two writers reading from the same `feeds`
  list instead of one (digest) plus a disjoint one (personal digest's separate list). The
  documented mitigation is the same as before: don't expect strict per-list dedup guarantees, and
  in this case, the `SPARK_HOUR` < `DIGEST_HOUR` ordering is what makes "Spark's pick doesn't
  repeat in the roundup" hold — a deploy that changes the hours to the opposite order gets that
  guarantee silently backwards. Worth a comment at the config default, not worth a schema change.
- No new persistence, no migration — Spark is pure logic reusing existing tables and columns.
```
